# TraceBase：第一版设计

## 目标与范围

面向开发者，把 README、配置说明、设计记录、排障文档整理为有版本、有证据的项目知识库。
第一版完成：空间 → 导入 → 索引 → 提问 → 核对原文 → 反馈 → 更新或删除。
后续才做 GitHub 增量同步、权限、OCR、冲突待审核、完整代码理解；不冒充已实现的能力。

## 技术决策

Vue 3 + TypeScript + Vite；Express 单服务；PGlite 0.5 + pgvector。
本机没有 Docker，选择实际运行 PostgreSQL 的嵌入式实现，而不是伪装成向量数据库的内存数组。数据库保留 SQL、事务与向量距离能力，但不是远程 PostgreSQL 服务、多进程共享库或生产级 HA。
没有 Redis、对象存储和单独任务服务。文档原文件以 bytea 保存，索引任务状态落库。服务重启将 indexing 任务恢复为 pending。队列串行，问答最多2个并发。

## 数据一致性

spaces、documents、revisions、chunks、answers 五张表。
文档 revision 是待处理的最新版本，active_revision 是当前可检索版本；二者在更新时可以不同。

1. 上传原文件与增加版本在同一事务内完成。
2. 索引器提取正文，单片最多850字符，长段以700字符步进保留150字符重叠。
3. 模型请求在事务外进行，不长期锁住数据库。全部新片段准备好后，在同一事务内删除旧索引、插入新索引、切换 active_revision。
4. 事务前检查文档仍存在且 revision 未变，过期任务不得覆盖新上传。
5. 解析失败保留旧索引；向量服务失败则提交关键词索引并显示警告。
6. 删除级联清理版本和片段，同时清除引用该文档的历史回答。问答保存前再次核对所有证据仍有效，避免删除或更新期间的悬空引用。
7. 更新保留历史回答快照。打开旧引用时对比当前片段，明确标为历史版本，不冒充现行规则。

## 检索与生成

- 英文词项与中文双字去重索引；关键词候选按匹配项数量排序，前18条。
- embedding 使用独立 HTTPS 服务，批量16条，维度2–4096。记录 endpoint + model 的哈希标签；查询过滤标签和维度。服务端不接受客户端指定模型地址。
- 同一模型标识下服务端更换权重无法自动发现，需主动重新索引。向量仅做小规模精确扫描，第一版没有 ANN 扩展与大库性能承诺。
- 语义候选余弦相似度大于0.45，前18条；RRF常数60融合，最多6段上下文。排序分不是置信度，阈值是初始配置，不是准确率保证。
- 当前空间过滤在数据库查询阶段完成，不靠模型提示词隔离。
- DeepSeek 只读取候选证据与问题。提示词将文档视为不可信数据，不执行文档指令。输出1–4段，每段至少一个引用。
- 校验 JSON、长度、引用ID与逐字摘录。验证不能证明语义支持；无 Key、超时、无效引用时回退摘录，无候选则拒答。
- SSE 发送检索进度；生成完毕并校验后才发送段落和最终结果，避免先展示幻觉再撤回。

## 界面

左侧空间与导航；资料页展示状态/当前版本/有效片段；问答页展示答案、引用与最近30条历史；右侧展示完整有效文档分段与定位高亮；健康页汇总索引错误和最近30条中的不准确反馈。
不将旧更新时间自动判为过期，不自动确定冲突资料谁对谁错。后续评估后再增加人工审核队列。

## 安全与部署边界

只监听127.0.0.1，检查Host与Origin，接口无跨站CORS。输入验证、参数化SQL、文件大小/页数/片段数量限制；前端仅渲染纯文本，不执行Markdown HTML。
模型端点须HTTPS且不允许重定向；不记录API Key，不向客户端发送密钥。文档和问答的敏感性由使用者判断。
仍无账户权限、磁盘加密、租户配额和恶意PDF独立进程沙箱；解析耗时可能影响单进程。不要将此版本当作公开上传服务。

## 后续验收方向

用实际项目语料建设固定问题与预期证据集，测量 Recall@k、无答案识别、引用支持率与耗时。GitHub同步需要增量游标、删除对账和版本来源；团队版需要权限在检索前过滤和可审计的外发策略。

## HTML 原型资料

新增 .html / .htm 上传类型，UTF-8 解码后通过 Cheerio 解析静态 DOM。移除脚本、样式、嵌入页面、模板及明确隐藏内容，保留标题层级、块元素边界、表格单元格、表单提示与图片替代文字，然后复用切分与索引流程。源码遵循8MB上传限制，提取文字遵循15万字符/300片段限制。

不执行 JavaScript、不请求外部资源、不渲染 HTML；原文定位展示提取文字。外部CSS决定的显示状态不作判断。纯脚本页面明确报错，失败保留旧版索引；截图、画布内容和页面交互不在本轮范围内。

## 动态原型清洗与提示

HTML 在正文提取时剔除未解析的双大括号插值，支持跨行、嵌套对象和字符串内括号；标题、占位提示、实体解码后的文本均使用同一过滤规则。检测指令属性、模板文本或可执行脚本时记录静态提取不完整提示，不执行表达式。导航按 nav/role 与面包屑语义识别；只有存在明确 main/role=main 正文时，才去除其外部常见侧栏，保留正文内的菜单说明。

新增 documents.extraction_warning 可空字段，启动时使用 ADD COLUMN IF NOT EXISTS 兼容现有数据库。提示与有效索引在同一事务切换：新版失败保留旧提示；静态新版成功清除旧提示。检索证据携带该字段到模型、回答和引用快照，提示不计入原文内容或向量。已有索引不自动重建，需用户手动重试索引，不自动改写历史回答。

## 模型结果与错误分类

模型结果分 answered、insufficient、fallback。对外输出证据短编号S1–S6，程序映射回真实chunk UUID后仍检查逐字引用；不存在的来源或改写引文均拒绝。模型只能引用content，不能用标题、菜单入口或动态提示推断具体字段。

insufficient必须携带空sections且不得带额外结论字段；程序生成固定“无法确认”说明，mode=abstain，仍保留候选证据供人工查看，不回退摘录。HTTP401/402/403/404/429等、网络、超时、非JSON响应、无效输出结构、截断、引用来源不存在和引文不匹配使用独立安全提示，fallback保存errorCode用于核查，不保存上游错误正文或密钥。

不放宽引用检查，不自动改写模型引文，不自动重试付费请求。提示词和存在性检查仍不能证明语义绝对正确；资料不足识别需要继续用真实语料评估。
